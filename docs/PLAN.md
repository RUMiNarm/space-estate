# 宇宙物件ガイド ― 「その星で、生きられるか?」 実装プラン

> このファイルは ultracode(Claude Code)にそのまま渡す実装指示書。
> 参考動画 3 本(ゆる天文学ラジオ「移住マイスター」シリーズ)の字幕を解析して作成した。

---

## 0. コンセプト

**宇宙の物件検索サイト**。**住めない天体も含め、一次ソースにデータがある天体をできるだけすべて**「物件」として登録する。
対象は、太陽系の惑星・衛星・準惑星(候補を含む)・主な小天体・太陽と、確認済みの系外惑星すべて(数千件規模)。
ユーザーは「岩石」「ハビタブルゾーン内」「大気あり」などの**入居条件を順番に足しながら絞り込み**、
「宇宙服なしで何秒もつか」「どの装備なら住めるか」を科学的データで確認できる。

- 3 本目の動画で、出演者が「物件検索の条件に入れる」「惑星のレインズ(※不動産業者向けの物件情報サイト)見てる」「それ専門のサイト作って全部星を載せてる?」と話している。**動画の中で冗談として語られたサイトを実際に作る**、という位置付け。
- トーン:不動産サイト風(間取り・メリット・デメリット・入居条件・心理的瑕疵物件)で親しみやすくする。数値は正確に。
- 正確さ最優先:全数値に出典と確度(実測/推定/不明)を付ける。動画の中の誤りは最新値で正し、注記する。

### 1-3. サイトに取り入れる要素
1. **物件検索(段階的な絞り込み)**:③の「岩石→ハビタブルゾーン→大気→距離」をチェックボックス式のフィルタにする。条件を1つ足すごとに件数が減っていく様子と、「なぜこの条件が必要か」の解説を見せる。
2. **物件詳細フォーマット**:間取り(基本データ)・メリット・デメリット・入居条件・タグ(事故物件/心理的瑕疵物件/地面なし/間取りが変わる)。
3. **地球目線の換算**:1日・1年・重力・体重を地球基準で示す(天王星の昼42年、ハウメアで体重が変わる、など)。
4. **並び替え**:動画内の「発見順で並んでいる」「価格順、広さ順もある」を受けて、発見年・距離・ESI・重力・気温で並び替えられるようにする。
5. **アクセス(到達時間)**:光速/光速の半分/現在のロケット/ボイジャーで何年かかるか。
6. **シリーズ構成**:惑星編・準惑星編・系外惑星編に、動画でまだ扱っていない**衛星編**を加えて4カテゴリにする。

## 3. 判定モデル

### 3-1. 物件検索の条件(③の流れ+追加)
| 条件 | 判定方法 | 解説ページで説明すること |
|---|---|---|
| 岩石惑星 | 半径が地球の約1.6倍以下、または密度で判定。不明なら「不明」 | 液体の水と生命の誕生 |
| ハビタブルゾーン内 | 恒星の光度から内側・外側の境界を計算して判定(Kopparapu らの式) | 恒星が暗ければゾーンは近くなる |
| 大気・気圧がある | 実測/推定/不明の3値 | 気圧と水の沸点、恒星風、磁場 |
| 気温 | 範囲スライダー | 放射平衡温度と温室効果 |
| 重力 | 範囲スライダー | 体重換算 |
| 潮汐固定(いつも同じ面を恒星に向けている) | あり/なし/不明 | 昼側は灼熱、夜側は極寒 |
| 距離 | 光年 | 到達時間 |

**「不明」の扱い**:系外惑星はデータの欠けが多い。絞り込みで「不明を含める/除外する」を選べるようにする。

### 3-2. 生身で生き延びられる時間(宇宙服なし)
物理値から最も早く死に至る要因を決め、その文献値をレンジ(幅)で返す。断定しない。
```
優先順位(上から評価し、最初に当てはまったものを採用):
  1. 地表なし(ガス惑星・恒星)          → 落下・圧壊・高温(秒〜分)
  2. 気温が極端(数百°C以上)            → 熱による即死(秒)
  3. 気圧が極端(数十気圧以上)          → 圧壊(秒)
  4. アームストロング限界(約0.063気圧)未満
                                      → 真空・低圧:約15秒で意識喪失、約1〜2分で死亡
  5. 酸素分圧が不足                      → 窒息:約1〜3分で意識喪失
  6. 極低温                              → 低体温(分〜時間)
  7. 放射線                              → 急性放射線障害(時間〜日)
  データが不明                           → 「判定不能(データ不足)」と明示する
```

### 3-3. 装備レベル(入居条件)
| Lv | 名称 | 例 |
|---|---|---|
| 0 | 普段着で OK | 地球 |
| 1 | 酸素マスクと防寒具 | (フェーズ2)タイタン |
| 2 | 与圧服(宇宙服) | 月・火星・ケレス・冥王星 |
| 3 | 特殊な遮蔽が必要 | 水星の昼側、放射線の強い場所 |
| 4 | 現在の技術では入居できない | 金星の地表・ガス惑星・太陽・CoRoT-7b |
| ? | データ不足で判定できない | プロキシマb(大気の有無が不明)など |

### 3-4. 地球類似性指標(ESI)
- Schulze-Makuch ら(2011)の式で、半径・密度・脱出速度・表面温度から自前で算出する。
- PHL(居住可能惑星研究所)のカタログ値も併記し、値が違う理由(算出に使ったパラメータの違い)を注記する。

### 3-5. アクセス(到達時間)
`距離[光年] ÷ 速度[光速比]` を光速・光速の50%・光速の10%・ボイジャー1号(約17km/s)・一般的なロケット(光速の約1万分の1)で表示する。

### ロジック(`src/lib/`)
- `habitableZone.ts`:主星の光度・温度からハビタブルゾーンの境界を計算する(Kopparapu ら 2013/2014)

## 6. データの出典(一次ソースのみ)

### 6-1. 一次ソースの定義
- **使ってよいもの**:宇宙機関・観測機関の公式データベースと公式ファクトシート、IAU/MPC の公式発表、査読論文(DOI か ADS の bibcode で特定できるもの)。
- **使わないもの**:Wikipedia、まとめサイト、ニュース記事、AI の回答、私(Claude)の記憶。存在を知るきっかけにするのは構わないが、数値は必ず一次ソースから取る。
- NASA Exoplanet Archive の値は論文から集めたものなので、値ごとの参照論文(`*_reflink` 列)も保存し、物件ページに論文へのリンクとして表示する。

### 6-2. 出典一覧
| 用途 | 一次ソース | 取得方法 |
|---|---|---|
| 惑星・月・太陽の物理値 | NASA Planetary Fact Sheet(nssdc.gsfc.nasa.gov/planetary/factsheet/) | HTML の表をパースする |
| 衛星の物理量・軌道・発見状況 | JPL Solar System Dynamics(ssd.jpl.nasa.gov/sats/) | HTML の表をパースする |
| 準惑星・小惑星・彗星 | JPL Small-Body Database API(ssd-api.jpl.nasa.gov/sbdb.api、sbdb_query.api) | JSON API |

| 系外惑星・主星 | NASA Exoplanet Archive TAP(`pscomppars`) | ADQL クエリで CSV/JSON を取得 |

### 6-3. ルール
- 取得スクリプトは `data/raw/<source>/<取得日>.json` にそのまま保存し、正規化は別の工程で行う(取り直しと差分確認ができるようにする)。
- 全数値に `sourceId` を付ける。出典のない値は表示しない(「不明」と表示する)。
- 変わりやすい値(衛星数、系外惑星のパラメータ)には `asOf` を付け、取得日を表示する。
- NASA Exoplanet Archive が求める謝辞をサイトに記載する。
- 動画の文章をそのまま転載しない。参考動画と参考書籍は「参考」としてリンクだけ載せる。

## 7. 実装ステップ(ultracode に渡す順序)

1. **雛形を作る**:`pnpm create astro`、TypeScript strict、Tailwind、Preact、Vitest、ESLint、Prettier。
2. **スキーマと出典**:`content.config.ts` に Zod スキーマを定義し、`sources.yaml` を作る。
3. **取得スクリプト**:`scripts/fetch/` に、NASA Fact Sheet・JPL SSD(衛星)・SBDB(小天体)・Exoplanet Archive(系外惑星)の4つを作る。生データを `data/raw/` に保存する。
4. **正規化**:`scripts/normalize/` で共通スキーマに変換し、単位をそろえ、`sourceId` と確度を付ける。異常値チェック(負の半径、単位の取り違えなど)をテストにする。
5. **ロジックとテスト**:`habitableZone` / `survival` / `equipment` / `esi` / `travel` / `search` を作り、段階Aの期待値テストを通す。全件に判定を適用し、「判定不能」の件数をレポートに出す。
6. **段階Aのコンテンツ**:手書きのメリット・デメリット・キャッチコピー・名前の由来。§1-4 のファクトチェックを一次ソースで確認してから反映する。
7. **段階Bの自動生成文**:データから説明文を作るテンプレート(例:「主星からの距離は地球と太陽の距離の◯倍で、ハビタブルゾーンの内側にあります」)。
8. **物件詳細・惑星系ページ**:実測/推定/不明のバッジと出典リンク(論文リンクを含む)を付ける。
9. **物件検索・カタログ**:フィルタ、外れた理由の表示、並び替え、仮想スクロール。数千件で操作が遅くならないことを確認する。
10. **ガイド付き検索**:③の4ステップを追体験する形式。
11. **比較・ランキング・解説・判定方法ページ**。
12. **仕上げ**:レスポンシブ(スマホ幅375pxで横スクロールなし)、ダーク/ライト、OGP、アクセシビリティ。
13. **E2E とデプロイ**:Playwright で主要ページと検索を確認し、GitHub Actions でデプロイする。データ更新用の定期実行ワークフロー(取得→正規化→差分を PR にする)も作る。
14. **拡張**:段階Aの追加、パラメータを動かせるシミュレーター、極端な天体(白色矮星・中性子星など。一次ソースのデータがあるものに限る)。
